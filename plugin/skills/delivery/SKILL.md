# Promise to delivery

Recommend the smallest useful next step linked to the selected clip and programme: a DM exercise, text template, existing material, or optional personal review. A new PDF is not the default.

For an interview example: Reel demonstrates one concrete answer; CTA asks for EXAMPLE; the first DM delivers "Situation: __. My action: __. Result I can verify: __." Then offer to review the person's draft. This is illustrative copy, not verified subscriber delivery. Write actual campaign copy in the coach's language and voice.

Keep the Reel CTA, caption, keyword, first reply and benefit consistent. Save exact text in delivery.json with the selected account/post identifiers and recipient scope. For existing material, verify the real destination from the recipient side and its permission; a public-looking URL alone does not prove access. Do not upload private material to make a link work.

Demonstrate practical use before offering blanks. Deliver one filled worked example for the programme's audience, then a small exercise they can apply. Identify invented example facts as illustrative. Distinguish the coach's original exercise from the source author's words. Show the decision, verified observations, a plausible alternative, a revised statement and what remains uncertain. Do not imply the exercise was taught or endorsed by the source speaker. Write the exact complete first message, not a placeholder that requires manual substitution.

Use only existing connected Chatfuel tools, with their actual schemas. Inspect only the relevant capabilities; never fabricate operations or change MCP/server. The checked catalogue has no feed/Reel publisher; treat publication as unavailable until new evidence establishes a permitted operation. New-file transfer into the connector is unverified. Stop those branches explicitly, while completing local content and text benefit preparation. Do not substitute coach copy/paste, manual upload, a website, new service or another connector silently.

Before mutation, show the exact account, post, rule, messages, recipients, side effects and shutdown steps. Obtain permission for that specific test. Re-read current state and remote configuration immediately before acting. Reconcile existing rule IDs before creating anything. Record a scoped pending action before mutation; unknown results require remote history reconciliation, not retry. No local helper executes remote actions.

Read back configured text and enabled status. Test with a separately authorized subscriber. Claim delivery only after recipient-side evidence shows the promised benefit. A successful API response is configuration evidence only. Changing the promise, post, account, recipient or message requires renewed relevant approval.

## Optional personal review

Read actual subscriber answers and the coach's method. Show the source facts beside the draft, one useful next action and missing evidence. Do not invent diagnosis, programme eligibility or results. Coach edits and approves exact recipient and text. Re-read the latest answers before sending; new answers invalidate approval. Disclose that send_chat_message changes the conversation to manual mode. Returning AI control needs separate consent. Without atomic remote safeguards, disclose the residual race; do not claim absolute concurrency protection.

## Optional modes and completion

Background drafts require a separately approved native cloud task, no sends, verified notification setting, closed-client execution and accessible saved result. Do not add a scheduler. Booking is separately unimplemented here; a calendar link is not a confirmed booking.

To stop, use campaign's stop protocol: block local new actions, disable only this test rule, read back, stop a selected schedule separately, and verify a control comment. Preserve sent-message evidence; do not claim recall. If remote cleanup fails, report the exact rule still active and the necessary authorized action. Never claim full launch or shutdown from a local state transition.
